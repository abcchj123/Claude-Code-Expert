## 1. 제품 개요

**Tika**는 티켓 단위로 할 일을 관리하는 칸반 보드 TODO 앱이다.

| 항목 | 내용 |
|------|------|
| 제품명 | Tika |
| 유형 | 웹 앱 (SPA + API) |
| 대상 | 개인 사용자 (MVP 기준 단일 사용자) |
| 핵심 가치 | 티켓 기반의 직관적인 상태 관리와 일정 추적 |

사용자는 할 일을 **티켓**으로 등록하고, 4개의 고정 컬럼(Backlog / TODO / In Progress / Done)을 통해 작업 흐름을 시각적으로 관리한다. 드래그 앤 드롭으로 상태를 전환하며, 각 티켓에는 계획 시작일·계획 종료일·실제 종료일을 기록해 일정 준수 여부를 파악할 수 있다.

## 2. MVP 범위

MVP는 **단일 사용자의 로컬 환경 사용**을 전제로 한다. 인증 없이 접근 가능하며, 아래 기능으로 제한한다.

### 포함 항목

| 분류 | 내용 |
|------|------|
| 사용자 | 단일 사용자 (인증 없음) |
| 컬럼 | 고정 4컬럼: **Backlog · TODO · In Progress · Done** |
| 티켓 CRUD | 생성·조회·수정·삭제 |
| 상태 전환 | 드래그 앤 드롭으로 컬럼 간 이동 |
| 날짜 필드 | 계획 시작일 (`plannedStartDate`) · 계획 종료일 (`plannedEndDate`) · 실제 종료일 (`actualEndDate`) |
| 티켓 순서 | 동일 컬럼 내 수직 순서 변경 |

### 핵심 제약

- 컬럼 이름·개수는 변경 불가 (고정 상수)
- 티켓 1개는 반드시 하나의 컬럼에 속함
- 삭제는 소프트 삭제 없이 즉시 영구 삭제

## 3. 2차 제외 범위

아래 기능은 MVP에 포함하지 않는다. 구현 시 향후 확장성을 고려하되, 현재 코드에 관련 로직을 선 구현하지 않는다.

| 기능 | 제외 사유 |
|------|-----------|
| 사용자 인증 (로그인/회원가입) | 단일 사용자 MVP로 범위 축소 |
| 커스텀 컬럼 (추가·수정·삭제) | 고정 4컬럼으로 복잡도 제거 |
| 멀티 사용자 / 팀 기능 | 협업 기능은 2차 스펙 |
| 라벨 / 태그 | 분류 기능은 2차 스펙 |
| 코멘트 / 활동 로그 | 협업·히스토리 기능은 2차 스펙 |
| **파일 업로드** | **2차 스펙 — MVP에서 완전 제외** |
| 알림 / 이메일 발송 | 외부 서비스 연동은 2차 스펙 |
| 대시보드 / 통계 | 분석 기능은 2차 스펙 |

## 4. 사용자 시나리오

### US-01: 할 일 등록

```
1. 사용자가 Backlog 컬럼 하단의 "+ 티켓 추가" 버튼을 클릭한다.
2. 티켓 생성 모달이 열린다.
3. 제목(필수), 설명(선택), 계획 시작일, 계획 종료일을 입력한다.
4. "저장" 버튼을 클릭하면 티켓이 Backlog 컬럼 하단에 추가된다.
```

### US-02: 상태 이동

```
1. 사용자가 티켓 카드를 드래그한다.
2. 원하는 컬럼(TODO / In Progress / Done)으로 드롭한다.
3. 티켓의 status가 변경되고 해당 컬럼에 표시된다.
4. Done 컬럼으로 이동 시 실제 종료일이 자동으로 오늘 날짜로 설정된다.
```

### US-03: 티켓 수정

```
1. 사용자가 티켓 카드를 클릭한다.
2. 티켓 상세/수정 모달이 열린다.
3. 제목·설명·날짜를 수정하고 "저장"을 클릭한다.
4. 변경 내용이 즉시 보드에 반영된다.
```

### US-04: 티켓 삭제

```
1. 사용자가 티켓 카드의 삭제 버튼(휴지통 아이콘)을 클릭한다.
2. 삭제 확인 다이얼로그가 표시된다.
3. "삭제"를 확인하면 티켓이 영구 삭제된다.
4. 보드에서 해당 카드가 즉시 제거된다.
```

### US-05: 완료 처리

```
1. 사용자가 In Progress 상태의 티켓을 Done 컬럼으로 드래그한다.
2. 실제 종료일이 오늘 날짜로 자동 입력된다.
3. 티켓 카드에 완료 표시(취소선 또는 뱃지)가 노출된다.
4. 사용자는 수동으로 실제 종료일을 수정할 수 있다.
```

## 5. 핵심 기능 목록

REQUIREMENTS.md의 FR-001~008과 대응하는 기능을 정의한다.

| ID | 기능명 | 설명 | 우선순위 |
|----|--------|------|----------|
| **FR-001** | 티켓 생성 | 제목(필수), 설명(선택), 계획 시작일, 계획 종료일을 입력해 새 티켓을 생성한다. 초기 상태는 Backlog. | Must |
| **FR-002** | 티켓 목록 조회 | 전체 티켓을 컬럼별로 그룹화해 보드에 표시한다. 컬럼 내 position 기준으로 정렬한다. | Must |
| **FR-003** | 티켓 상세 조회 | 티켓 카드 클릭 시 모달로 상세 정보(제목·설명·상태·날짜)를 표시한다. | Must |
| **FR-004** | 티켓 수정 | 제목·설명·날짜 필드를 수정하고 저장한다. 상태 변경은 FR-005를 통해서만 가능하다. | Must |
| **FR-005** | 티켓 삭제 | 확인 절차 후 티켓을 영구 삭제한다. | Must |
| **FR-006** | 드래그 앤 드롭 상태 전환 | 티켓을 다른 컬럼으로 드래그해 status와 position을 함께 업데이트한다. Done 이동 시 actualEndDate 자동 설정. | Must |
| **FR-007** | 컬럼 내 순서 변경 | 동일 컬럼 안에서 티켓을 위아래로 드래그해 표시 순서를 변경한다. | Should |
| **FR-008** | 날짜 관리 | 계획 시작일(`plannedStartDate`)·계획 종료일(`plannedEndDate`)·실제 종료일(`actualEndDate`) 3개 날짜 필드를 독립적으로 입력·수정한다. | Must |

## 6. 기술 스택

### 선정 스택 요약

| 분류 | 기술 | 버전 | 선정 이유 |
|------|------|------|-----------|
| **Framework** | Next.js App Router | 15 | 프런트엔드·백엔드를 단일 레포에서 관리 (Route Handlers). Vercel 배포에 최적화. |
| **Language** | TypeScript (strict) | 5.x | 타입 안전성 확보. 프런트·백엔드 shared 타입으로 인터페이스 계약 보장. |
| **Frontend** | React | 19 | Server Components + Client Components 혼용으로 성능·DX 균형. |
| **Styling** | Tailwind CSS | 4 | 유틸리티 클래스로 빠른 UI 구성. 디자인 토큰을 `colors.json`으로 관리. |
| **Drag & Drop** | @dnd-kit/core + @dnd-kit/sortable | latest | 접근성(ARIA) 내장, SSR 친화적. react-beautiful-dnd 대비 React 19 호환성 우수. |
| **ORM** | Drizzle ORM | 0.38.x | 타입 안전한 쿼리, 경량 번들. Prisma 대비 Vercel Edge 환경 호환성 높음. |
| **Database** | PostgreSQL | 16 | 로컬: node-postgres, 배포: Vercel Postgres. ACID 트랜잭션으로 position 정합성 보장. |
| **Validation** | Zod | 3.x | Runtime 검증 + TypeScript 타입 추론 동시 처리. 프런트·백엔드 스키마 공유. |
| **Testing** | Jest + React Testing Library | latest | 서비스 단위 테스트(Jest)와 컴포넌트 통합 테스트(RTL)를 단일 러너로 실행. |
| **Deployment** | Vercel | — | Next.js 공식 플랫폼. Zero-config 배포, Preview URL, Vercel Postgres 통합. |

| 영역 | 역할 | 비고 |

| **좌측 사이드바** | Backlog 전용 컬럼 | 고정 너비(~280px), 스크롤 가능 |
